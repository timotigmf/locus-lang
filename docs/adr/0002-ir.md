# ADR 0002 — IR esplicita e dominio esterno

Stato: accettato, 2026-09-25.

Alternative: interpretare AST (rapido, ma runtime legato alla sintassi); compilare
Python (backend comodo, ma semantica/portabilità/sandbox legate a Python); bytecode
(compatto, troppo presto per decidere VM e opcodes); IR dichiarativa tipata.

Decisione: dataclass frozen per AST e IR distinte. IR con versione interna, ID
risolti e label di presentazione; mondo iniziale costruito solo dall'IR. JSON per
ispezione, non per persistenza o protocollo stabile. Oggi un solo passaggio
semantico/lowering basta; due passaggi quando arrivano riferimenti.

Catalogo tipi esplicito e passato dal composition root; nessun tipo IF hardcoded
nel compilatore. La stdlib Python iniziale è sostituibile dal chiamante. Evitare
un sistema di plugin generico prima di avere due casi reali di estensione.

Conseguenze: più modelli piccoli, ma nessuna dipendenza del runtime dall'italiano.
Gli ID ordinali non possono identificare oggetti in salvataggi dopo modifiche al
programma. Prima di save/restore definire ID persistenti, source map, schema
validato e migrazioni. Prima di backend browser estendere l'IR con valori ed
effetti a semantica indipendente da Python, verificata con suite di conformità.
